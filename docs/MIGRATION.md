# Kotlin/JS 이식 계획

## 기준 및 범위

- 기준: 사용자가 제공한 `DCRefresher-Reborn-develop.zip`의 **6.2.2** 소스 및 `docs/` 개발 문서.
- 이 저장소는 **독립 Private 저장소**이며 GitHub Fork 관계를 만들지 않는다.
- 목적: 핵심 기능과 화면을 **Kotlin으로 작성·유지보수**하고, Kotlin/JS가 브라우저용 JavaScript를 생성해 Chrome 확장으로 빌드한다.
- JavaScript/TypeScript가 반드시 필요한 경계가 확인되면 그 부분만 최소화한다. 단순히 언어를 통일하기 위해 기능 안정성을 희생하지 않는다.
- 원본 소스를 통째로 복사해 완성된 Kotlin 버전이라고 표시하지 않는다.

## 원본에서 보존할 계약

원본 `docs/architecture.md`, `docs/modules.md`, `docs/ui.md`, `docs/testing.md`를 기준으로 동작을 대조한다.

1. **모듈 ID 및 설정 키 호환성**: 기존 설정 스키마와 백업/복원 포맷을 보존한다.
2. **조건부 로딩**: 활성화한 모듈만 로드하고, 비활성 모듈이 불필요하게 실행되지 않도록 한다.
3. **실행 컨텍스트 분리**: content script, background service worker, MAIN world의 실행 위치와 권한을 혼동하지 않는다.
4. **종료 처리**: 모듈을 끄거나 확장 컨텍스트가 무효화될 때 이벤트·관찰자·구독을 정리한다.
5. **UI 호환성**: 팝업, 옵션, Shadow DOM 오버레이, 스타일 및 포커스 동작을 보존한다.
6. **브라우저 호환성**: Chrome Manifest V3 우선, Firefox 별도 검증. 기존 최소 버전(Chrome 140/Firefox 144)을 변경할 때 근거를 기록한다.
7. **설정 이전**: 새 확장의 ID/저장소 영역은 원본 확장과 다를 수 있다. 기존 백업 형식을 유지하고 실제 내보내기/가져오기를 검증한다.

## 단계와 완료 기준

| 단계 | 작업 | 완료 기준 |
| --- | --- | --- |
| 0 | 독립 Private 저장소와 개발 기준 문서 | 저장소/커밋 확인 |
| 1 | Kotlin/JS → 실제 MV3 Chrome 확장 ZIP으로 빌드하는 최소 검증 | Kotlin 코드로 생성한 JS가 확장 내부에서 실행되고 빌드 산출물 확인 |
| 2 | 원본 6.2.2 동작 기준 확보 | 원본 단위/E2E 테스트 결과 또는 검증 불가 항목을 명시 |
| 3 | core(설정, 저장소, HTTP, 메시징, 모듈 수명주기) 이식 | 원본과 값·수명주기·오류 처리 비교 검증 |
| 4 | 기능 모듈 단계적 이식 | 11개 기능별 회귀 테스트 |
| 5 | 팝업/옵션/오버레이 UI Kotlin 전환 | UI 동작·CSS·포커스·설정 연동 검증 |
| 6 | 개인 패치 기능별 PR 이식 | 각 패치의 실제 동작과 회귀 테스트 통과 |
| 7 | GitHub Actions/Release | PR 검사 및 Chrome ZIP 자동 빌드·설치 검증 |

각 단계는 실제로 검증하기 전까지 **미완료**다. 도구·환경 제약으로 검사할 수 없는 것은 통과로 처리하지 않는다.

## 개인 패치 이식 목록(원본 코드와 별도 검증)

- YouTube 본문: iframe/embed → 원본 링크 → 높이 1px 문단 → OG 카드 → 일반글의 순서, `<p><br></p>` 유지.
- 디시콘 패키지 가로 휠: 기존 실사이트 검증된 **wheel 이벤트 캡처**와 `scrollLeft += deltaY` 동작 보존. 동작 방식 변경 시 별도 근거·검증 필수.
- 다크모드 색상/반전 보정.
- 미리보기·댓글 관련 개인 동작 보존.
- Cloudflare Turnstile 관련 호환성: 원본의 현재 상태와 개인 변경사항을 비교한 뒤 필요한 변경만 이식.

패치가 이미 원본에 포함된 경우 중복 구현하지 않는다. 패치마다 별도 브랜치/PR을 사용한다.

## 원칙

- Kotlin 중심으로 개발하되, 브라우저가 Kotlin을 직접 실행하는 것으로 오해하지 않는다.
- 기존 기능의 사양 변경·추측 기반 리팩터링·무관한 정리를 하지 않는다.
- 원본의 GPL-3.0 및 저작권 고지를 존중한다.
- 빌드 성공과 실제 사이트 정상 동작을 구분해서 보고한다.
